# 管理员使用说明

本项目已有管理员 Auth 用户及 admin_users 成员，生产兼容迁移已于 2026-11-25 应用。已有管理员直接使用原邮箱和当前密码登录，无需再次注册；重置密码后使用新密码。

## 登录

进入[正式管理后台](https://sherlockedjim.github.io/sweet-lucky-draw/#/admin)，使用管理员邮箱和当前密码登录。部署授权用的一次性验证码不作为网站密码。系统不能读取原密码。

只有 UUID 位于 public.admin_users 的 Auth 用户可以进入后台。以后新增管理员时，先在现有项目的 Authentication → Users 创建 Auth 用户，再将该用户 UUID 加入 admin_users；已有管理员无需重复注册。

## 忘记密码

1. 打开[找回密码](https://sherlockedjim.github.io/sweet-lucky-draw/#/admin/reset-password)，输入原管理员邮箱，点击“发送重置邮件”。
2. 到邮箱收件箱或垃圾邮件中打开最新的重置邮件；在网站页面输入并确认新密码，点击“保存新密码”。
3. 返回管理员登录页，用原邮箱和新密码登录。账号 UUID、管理员身份和活动记录保留。

密码至少 8 位，并须满足 Supabase 项目当前的密码规则。密码直接填在网页里，不要发到聊天或提交仓库。重置链接过期时重新申请邮件。页面返回成功提示只表示请求已受理，邮件送达仍需收件人检查。

若提示项目暂不能向此邮箱发送邮件，由项目所有者检查 Supabase → Authentication → Emails → SMTP Settings。Supabase 默认邮件服务通常只允许项目组织成员邮箱；其他地址需配置自有 SMTP。[官方邮件说明](https://supabase.com/docs/guides/auth/auth-smtp)。

## 生成和分发邀请码

1. 在后台点击“生成邀请码”。
2. 输入 1–500 的整数，确认生成。
3. 点击“复制全部”或“导出本批 CSV”，再把邀请码分发给参与者。

完整邀请码请在生成后保存。数据库只存哈希和末 4 位；刷新后的历史列表不会重新提供完整号码。

## 查询对应奖品

在“按完整邀请码查结果”输入 8 位完整邀请码，点击“查询结果”。已抽奖时显示对应奖品、抽奖时间和记录编号，可点击“在记录中定位”。查询只读取已有结果，不消耗邀请码。

也可以切换“中奖记录”，按末 4 位、奖品或记录编号筛选并导出 CSV。末 4 位可能重复，需要准确核对某一张邀请码时，使用完整邀请码查询。

## 查看数量和时间

概览显示邀请码总数、未使用数、已使用数和中奖记录数。邀请码表显示生成时间及使用时间；中奖记录显示奖品和抽奖时间，均按北京时间显示。

六礼盒规则下，三个空盒的结果均为“送你一天的开心～”，也会记入已使用数和抽奖记录；该结果是一份开心寄语，不兑换实物。按完整邀请码查询及 CSV 导出同样支持这个结果。

## 昵称与头像

参与者必须先填写昵称并选择头像，才能使用邀请码。头像支持 JPG、PNG、WebP，最大 8MB，由浏览器裁剪、压缩为 256×256 JPEG，再与中奖结果在同一事务中保存到 Supabase。

后台“中奖记录”最左侧显示头像和昵称；搜索框支持昵称、邀请码末 4 位、奖品和记录编号。CSV 包含昵称和头像是否已保存，图片在后台查看，不嵌入 CSV。

历史记录显示“历史未记录”，因为旧版本没有把这些资料上传。请让旧参与者用原邀请码找回结果，填写资料并点击“补充到中奖记录”。支持从同一浏览器旧缓存预填，但不会自动上传。补填只执行一次，奖品、抽奖时间和编号保持原值。

新记录的昵称头像以抽奖时快照为准，刷新、换设备凭原码可恢复。手动昵称头像不是微信身份认证；兑奖仍需核对邀请码、记录编号和奖品。
